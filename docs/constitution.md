# Constitución del proyecto: v-note

1. **Stack mínimo.** TypeScript estricto + React + Vite + Bun; estilos con Tailwind y Radix; editor con BlockNote; SQLite local; Yjs para el documento; escritorio con Tauri 2 (Electron solo como plan B) y PWA para la web; pruebas con Vitest y Playwright. Ninguna dependencia nueva sin justificarla en el plan de la spec activa.
2. **La spec manda.** Todo cambio de comportamiento parte de una spec en `specs/` y todo cambio técnico de su plan; si código y spec difieren, se corrige primero la spec. La entrega sigue los hitos del plan: no se empieza un hito hasta cerrar el anterior.
3. **Lógica separada de la interfaz y de la plataforma.** La lógica de dominio (páginas, bloques, propiedades, fórmulas, exportación) vive en `packages/core` y no importa nada de React, del DOM ni de Tauri; las pantallas solo presentan y llaman al núcleo. Lo que depende de la plataforma (almacenamiento, llavero, planificador, ventana) va únicamente en la capa adaptador, para poder cambiar Tauri por Electron sin tocar el núcleo.
4. **Tests obligatorios.** Toda regla de datos (fórmulas, filtros, orden, exportación, respaldo y restauración) lleva prueba, y `bun run typecheck` y `bun run test` pasan antes de cerrar una tarea.
5. **SQLite local es la única fuente de verdad.** Todo dato persistente vive en la base del dispositivo, la app funciona completa sin internet y el esquema solo cambia mediante migraciones versionadas. Las escrituras son atómicas, borrar manda a la papelera antes del borrado definitivo, y ninguna operación (importar, restaurar, migrar) sobrescribe datos sin confirmación explícita.
6. **Respaldo a GitHub abierto y privado.** El respaldo exporta Markdown y JSON sin pérdida, sin cifrar, a un repo privado; la salida es determinista, con un solo commit por ciclo y ninguno si no hubo cambios, y debe poder restaurarse por completo. Es lo único que sale del equipo (sin telemetría ni servicios de terceros), y el token de GitHub vive solo en el llavero del sistema: nunca en el repo, en logs ni en archivos de configuración.
7. **Idioma.** Identificadores y código en inglés; textos de interfaz, mensajes y documentos de usuario en español de México, con i18n (es/en) desde el inicio. El nombre del proyecto vive en un solo lugar de configuración, porque puede cambiar.
